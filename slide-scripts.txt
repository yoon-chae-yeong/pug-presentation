# AI PUG 성장 히스토리

안녕하십니까.
AI Power User Group 운영진으로 활동하고 있는 AI솔루션팀 윤채영입니다.

오늘 제가 소개해 드릴 내용은 사내 AX 활동의 중심축 중 하나인 PUG(피유지) 이야기입니다.
여기 계신 분들이 각 팀의 리더분들이시다 보니 오가며 한 번쯤은 들어보셨을 텐데요.

이번 상반기 동안 멤버들과 어떤 고민과 실습을 해왔는지 핵심활동 위주로 공유해 드리겠습니다.
하반기 참여를 고민 중인 부서라면 오늘 내용이 좋은 참고가 될 것 같습니다.

그럼 AI PUG 성장 히스토리, 지금 시작하겠습니다.

-------------------
# AI PUG의 시작 - AI 활용과 문화 확산

바로 본론으로 들어가 보겠습니다.
PUG는 2025년 7월에 사내 AI 문화 확산과 현업 활성화를 목표로 첫발을 뗐습니다.

전사적으로 AI에 대한 관심은 뜨거웠지만, AI 업무에 녹여내고싶다는 실질적인 갈증이 컸던 것 같은데요
그러면서 현업 문제를 AI로 직접 풀어보고 서로의 사례를 나눌 수 있는 모임이 필요해지면서 PUG가 시작되었습니다.

여기 화면에 보이는 퍼그는 Power User Group의 약자인 PUG를 표현한 사진입니다.

-------------------
# 2025년 주요 활동

2025년에는 월 1회 정도 모임을 가지며 가볍게 시작해보았습니다.

서로의 AI 활용 팁을 나누는 것부터 시작해서, GPT나 Gemini를 활용한 바이브 코딩도 시도해보고, LLM 모델에 API를 직접 연동해보는 실습까지 진행했습니다.

그 과정에서 현업에 적용해볼 만한 결과물이 나오면 작게나마 사례 발표 세션도 가지면서 가능성을 확인했습니다.

-------------------
# 2026 운영 전략

하지만 2026년에는 운영 방식을 완전히 고도화했습니다.
가장 먼저 모임 주기를 주 1회 Full 타임(매주 수요일)으로 지정해, 하루 온전히 개발에만 몰입할 수 있는 실행 리듬을 만들었고,
여기에 디지털전략센터 실무진을 전담 매칭해 멤버들이 개발에만 집중할 수 있게 서포트했습니다.
그리고 보안 가이드와 개발 표준 가이드까지 제공해 산출물을 만드는 데 걸림돌도 없도록 지원했습니다.
무엇보다 AI를 '배우는 것'에 그치지 않고 '현업 문제를 직접 해결'할 수 있도록 실효성 중심의 12주 커리큘럼을 탄탄하게 준비했습니다.

-------------------
# AI PoC 개발 집중 환경 마련

구체적으로 멤버가 개발에만 집중할 수 있는 환경을 만들기 위해 지원해드렸고,
먼저 사내 전문가 연결을 통해 AI·개발·데이터·UI/UX 전반에 걸친 실무 맞춤형 강의를 진행했습니다.

코드 리뷰부터 사내 LLM Q&A, 머신러닝, UI/UX 피드백까지 디지털전략센터 실무진이 매주 함께 PoC 개발에 몰두했습니다.

그리고 실행력을 높이기 위해 온라인 강의를 선별해 제공하고, AI 유료 도구 구독과 API 키를 전폭 지원했습니다.

GitHub Organization과 표준 기술스택 가이드로 협업 기준을 통일했고, IT 기초 서적으로 비전공자와의 공통 언어를 맞췄습니다.
나아가 AI Playground와 API Playground를 통해 안전한 사내 LLM 실험은 물론, Outlook과 Teams를 연동하는 실제 PoC 환경까지 완성했습니다.

# 맞춤형 커리큘럼 · 교육 자료 (12주차)

커리큘럼 역시 비전공자도 스스로 시스템을 만들 수 있도록 설계했습니다.

코딩 기초부터 시작해 웹 시스템과 데이터베이스를 차근차근 다지고, Git 버전 관리와 실제 서비스 배포까지 실무 흐름 전체를 다뤘습니다.

실제로 주차별로 어떤 성장이 있었는지 이어지는 슬라이드에서 하나씩 보여드리겠습니다.

멤버들은 기본 문법과 변수·함수를 익히며 프로그래밍 기초 체력을 길렀고,
이를 통해 이후에 이어질 PoC 개발과 실습에 망설임 없이 참여할 수 있는 단단한 출발점을 만들었습니다.

# 3월 1주차 · 웹·시스템 구조 · 바이브 코딩
그 다음 3월 1주차부터는
바이브 코딩과 웹 시스템 구조를 중심으로 본격적인 실전에 들어갔습니다.

프론트엔드와 백엔드의 역할, 그리고 클라이언트–서버–API로 이어지는 데이터 흐름을 머릿속에 그렸습니다.
동시에 CLI, 터미널, 디버그 같은 필수 기초 용어들을 맞추면서,
이후 PoC를 만들 때 낯선 개발 용어 때문에 흐름이 끊기지 않도록 팀의 공통 언어를 확실하게 정립했습니다.

API를 보고 요청과 응답 흐름을 확인하면서 클라이언트-서버 통신을 AI와 함께 구현해보았고, 
테이블 생성부터 데이터 조회·수정 같은 실습도 진행했습니다.

이 과정을 통해 통신 구조를 이해하고 데이터베이스 기초를 확보하면서,
자신의 PoC에 직접 DB를 연동할 수 있는 기술 기반을 마련했습니다.

# 3월 3주차 · 생성형 AI · LLM · RAG

그 다음 주차에는 요즘 가장 뜨거운 생성형 AI, LLM, RAG를 집중적으로 다뤘습니다.

머신러닝·딥러닝 기초부터 NLP와 LLM의 차이, 프롬프트 파라미터 조율법까지 폭넓게 실습했고

사내 복지 가이드인 '슬기로운 DRB 생활' 데이터를 활용한 RAG 챗봇을 모든 멤버들이 직접 제작해봤습니다.

개념 이해를 넘어, 사내 데이터를 활용한 LLM 챗봇을 내 손으로 직접 구현해보는 주차였습니다.

# 3월 4주차 · RAG 챗봇 · 개인 발표
그리고 이어지는 주차에서는 
전 주에 배운 내용을 바탕으로 각자의 현업 데이터로 만든 RAG 기반 챗봇을 공유하는 시간을 가졌습니다.

어떤 현업 문제를 풀기 위해 어떻게 만들었는지 발표하고, 답변 정확도 개선법이나 최적의 모델 선택에 대해 질의응답을 나눴습니다.

이를 통해서 현업 도메인 문제에 AI를 직접 적용하는 실전 감각을 익히고, 동료들의 노하우까지 함께 흡수할 수 있었습니다.

# 3월 4주차 · RPA 자동화
같은 주에는 워크플로 자동화 툴인 n8n을 활용해 RPA 자동화도 마스터했습니다.

RSS 피드를 받아 ChatGPT로 요약한 뒤 Teams로 자동 전송하는 파이프라인과, 엑셀 기반 발표 순서 자동화 등을 실습했습니다.

복잡한 백엔드 코드를 짜지 않고도 강력한 자동화 흐름을 만들 수 있게 되면서, 실무에 즉시 쓸 수 있는 RPA 자동화 역량을 확보했습니다

-------------------
# 4월 1주차 · PoC 기획 · 아이디어 워크숍
다음으로 4월 1주차에는
개인별 PoC의 완성도를 높이기 위한 아이디어 워크숍을 열었습니다.

각 팀의 병목 업무와 현업에서 벌어지는 반복 수작업에 대해 정의하고, 
이를 AI로 어떻게 해결할지 토론하며 실행 가능한 설계 초안을 잡았습니다.

단순한 아이디어에 머무르지 않고, 당장 개발에 들어갈 수 있는 명확한 솔루션 기획안을 도출해냈습니다.

# 4월 3주차 · API 개발 심화 · 사내 LLM 연동

다음으로 4월 3주차에는 API 심화 개발과 사내 LLM 연동을 다뤘습니다.

FastAPI라는 프레임워크를 도입해 요청·응답을 정교하게 제어하고 API를 직접 검증해보고
AI 도구에 API 설계를 지시하고 코드를 받아내는 고급 프롬프팅 방식도 익혔습니다.

이로써 사내 LLM 연동과 API 설계 역량이 한층 강화되어, 
각자의 PoC에 필요한 백엔드 기능을 스스로 설계하고 검증할 수 있게 되었습니다.

-------------------
# 4월 3주차 · Git · GitHub
같은 주에 협업의 필수 도구인 Git과 GitHub도 체득했습니다.

내 PC에서만 작업하던 것을 넘어 원격 저장소로 코드를 올리고(Push) 내려받는(Pull) 실무 흐름과 기본 명령어들을 손에 익혔습니다.

현재는 모든 멤버가 PUG GitHub를 통해 체계적으로 코드를 관리하고 있어, 개발 실무자와 소통하는 데 문제가 없도록 코드 버전 관리 역량을 갖추게 되었습니다.

-------------------
# 4월 4주차 · BackEnd · FrontEnd · API 연동   <---------------------------다시------------------>
이어서Webhook과 전체 서비스 배포 흐름을 연결했습니다.

API로 웹훅 서버를 구축해 요청을 처리하고, 
프론트엔드 화면부터 서버, n8n, 그리고 Teams 알림까지 전체 파이프라인이 매끄럽게 이어지도록 실습했습니다.

프론트와 백엔드, DB가 실제로 어떻게 맞물려 돌아가는지 체득하면서, 
껍데기만 있는 화면이 아니라 실제 동작하는 엔드투엔드 서비스 구조를 완성했습니다.

# 4월 4주차 · UI/UX 기초
같은 주에 화면의 완성도를 결정짓는 UI/UX 기초도 다졌습니다.

단순히 디자인만 하는 것과 달리
실제 사용자의 경험을 생각하며 디자인 하는 것의 차이에 대해 배우고, 
Google Stitch 같은 AI 툴을 통해 디자인 전문가의 도움 없이도 UI 시안을 만드는 실습을 진행했습니다.

기능 구현에만 급급했던 단계에서 벗어나 사용자 중심 설계를 고민하게 되면서, 
실제 사용자가 쓰기 편하고 직관적인 화면을 기획할 수 있게 된 주차였던 것 같습니다.

단순 질의응답을 넘어, 복잡한 업무를 스스로 쪼개서 수행하는 자율형 에이전트 구조를 설계하는 역량까지 확보하게 되었습니다.

- 문제: 회의 하나를 잡기 위해 가능 시간 확인·회의실 조회·초대 발송 등 반복 조율이 많았습니다.
- 해결: 자연어 요청 → 일정 조회 → 가능 시간 수집 → 회의실 추천 → 예약·캘린더 등록 흐름을 구현했습니다.
- 효과: 회의 조율 시간과 커뮤니케이션 비용을 줄이고, 예약 채널을 하나로 모았습니다.

**강주혁님 · Check-Mate**
- 문제: 결산은 정확성·기한이 중요한데, 순서·의존관계·진행이 엑셀로만 관리되어 전체 흐름을 보기 어려웠습니다.
- 해결: 업무 선후행을 모델링하고 플로우맵·간트·캘린더·QnA·체크리스트로 결산 흐름을 시각화했습니다.
- 효과: 신규 담당자 진입 장벽을 낮추고, 병목 파악과 인수인계·업무 지식 자산화로 이어졌습니다.

**현재호님 · VEDA**
- 문제: 메일·Teams·Notion 등 업무 기록이 파편화되어, 외부 AI 없이 필요한 기록을 찾고 잇는 데 시간이 많이 들었습니다.
- 해결: 온프레미스 RAG로 이종 소스를 통합하고, 엔티티 정규화·검색 파이프라인으로 근거 기반 답변을 만들었습니다.
- 효과: Teams 회수율 약 18.8%→79.2%, Notion 약 29.2%→92.3%로 개선했고, 실제 업무 질의에 근거와 함께 회수했습니다.

**강응준님 · ATHENA**
- 문제: 정보는 많지만, 자료를 모으는 것과 의사결정에 쓸 지식으로 만드는 것은 달랐습니다.
- 해결: 자료를 수집·분류하고, 여러 AI 에이전트로 요약·딥다이브·리포트·팩트체크까지 구성했습니다.
- 효과: 흩어진 자료를 검색·질문·보고서 작성에 바로 쓰는 지식 자산으로 바꿨습니다.

# AI PUG Showcase · 멤버 PoC 발표
이어서 **2부** 네 가지 사례입니다.

**윤성수님 · 러버트랙 BOM**
- 문제: 신제품 견적·개발 시 SAP·BOM·엑셀 비교·부품 교체가 반복 수작업이었습니다.
- 해결: SAP·단가 업로드 시 자동 분류·재료비 계산과, 자연어로 조회·수정하는 에이전트를 만들었습니다.
- 효과: 조회 시간 절감, 숙련 의존도 감소, 재료비 계산 표준화와 오류 방지로 이어졌습니다.

**김진용님 · 임가공비 분석**
- 문제: 외주 견적의 적정성 판단이 어렵고, 담당자 경험에 따라 절감액·기준이 달라졌습니다.
- 해결: 업체 견적과 DRB 표준 시트를 비교해 과다 청구·협의가를 산출하고 3단계로 검증했습니다.
- 효과: 견적 검토가 수십 분~1시간에서 수초 수준으로 줄고, 협상 근거와 기준이 통일됐습니다.

**박지훈님 · 수율 대시보드**
- 문제: 스크랩·불량·수율 데이터가 여러 엑셀로 나뉘어 취합과 원인 분석에 시간이 오래 걸렸습니다.
- 해결: 데이터를 DB화·대시보드로 시각화하고, 자연어 질의로 DB 기반 원인 분석을 붙였습니다.
- 효과: 가독성과 분석 접근성이 좋아지고, 수작업 취합 시간이 줄었습니다.

**박다솜님 · 촉각 센서 분석 자동화**
- 문제: 힘 데이터와 정전용량 신호가 따로 나와 동기화가 어렵고, 분석자마다 해석이 달랐습니다.
- 해결: 구간별 감지·동기화와 보정·분할·분석·리포트, 해석 챗봇까지 자동화했습니다.
- 효과: 분석 시간이 약 8배 단축되고, 결과 포맷이 일관되며 데이터 신뢰도가 높아졌습니다.

발표를 통해 서로의 사례를 참고하고, **AI 활용 아이디어가 조직으로 확산**되는 계기가 되었습니다.
