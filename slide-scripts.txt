# AI PUG 성장 히스토리

안녕하십니까.
AI Power User Group 운영진으로 활동하고 있는 AI솔루션팀 윤채영입니다.

오늘 제가 소개해 드릴 내용은 사내 AX 활동 중 하나인 PUG(피유지) 인데요
여기 계신 분들은 각 팀의 리더분들이시다 보니 PUG에대해 어느정도 들어보셨을 거 같습니다.

이번 상반기 동안 PUG 멤버들과 어떤 활동을 해왔는지 핵심활동 위주로 공유해 드리겠습니다.
하반기 참여를 고민 중인 팀원이 부서에 있다면
오늘 내용이 좋은 참고가 될 것 같습니다.

그럼 AI PUG 성장 히스토리, 공유드리겠습니다.

-------------------
# AI PUG의 시작 - AI 활용과 문화 확산

바로 본론으로 들어가서
PUG는 2025년 7월에 사내 AI 문화 확산을 목표로 첫발을 뗐습니다.

PUG 출범 전 전사적으로 AI에 대한 관심은 뜨거워졌지만, 
AI를 혼자학습하기 어렵다는 의견들이 많았던 것 같은데요

이를 위해 현업 문제를 AI로 직접 풀어보고 서로의 사례를 나눌 수 있는 모임인 PUG가 시작되었습니다.

여기 화면에 보이는 퍼그는 Power User Group의 약자인 PUG(피유지) 퍼그 사진입니다.

-------------------
# 2025년 주요 활동

2025년에는 월 1회 정도 모임을 가지며 가볍게 활동을 시작해보았습니다.

AI 활용 팁을 나누는 것부터 시작해서, GPT나 Gemini 모델을 활용한 바이브 코딩도해보고, 
LLM 모델에 API를 직접 연동해보는 실습까지 진행했습니다.

그 과정에서 현업에 적용해볼 만한 결과물이 나오면 
작게나마 사례 발표 세션도 가지면서 가능성을 확인했습니다.

-------------------
# 2026 운영 전략

하지만 2026년에는 운영 방식을 완전히 고도화했습니다.

가장 먼저 모임 주기를 주 1회 Full 타임(매주 수요일)으로 지정해, 
하루 온전히 개발에만 몰입할 수 있는 실행 리듬을 만들었고,

여기에 디지털전략센터의 웹,데이터,AI 개발 관련 실무진을 연결시켜 
멤버들이 개발에 집중할 수 있게 지원해드렸습니다.

그리고 보안 가이드와 개발 표준 가이드까지 제공해 
산출물을 만드는 데 걸림돌도 없도록 지원했고 (쉬고)
무엇보다 AI를 '배우는 것'에 그치지 않고 '현업 문제를 직접 해결'할 수 있도록 
실효성 중심의 PUG 맞춤형 12주 커리큘럼을 준비해서 운영했습니다.

# AI PoC 개발 집중 환경 마련

구체적으로는 매주 AI·개발·데이터·UI/UX 전반에 걸친 실무 맞춤형 강의를 진행했고

코드 리뷰부터 사내 LLM QnA, 머신러닝, UI/UX 피드백까지 제공해드렸습니다.

그리고 실행력을 높이기 위해 온라인 강의를 선별해 제공하고, AI 유료 도구 구독과 API 키를 전폭 지원했습니다.

원격저장소와 표준 기술스택 가이드로 코워킹 기준을 통일했고, 
IT 기초 서적 전원 배부로 비전공자가 개발을 이해할 수 있도록 공통 언어를 맞췄습니다.

나아가 AI Playground와 PUG API Playground를 통해 안전한 사내 LLM 실험과 함께, 
Outlook과 Teams를 연동하는 실제 PoC 환경까지 완성했습니다.

# 맞춤형 커리큘럼 · 교육 자료 (12주차)

커리큘럼 역시 비전공자도 스스로 시스템을 만들 수 있도록 설계했습니다.

코딩 기초부터 시작해 웹 시스템과 데이터베이스를 차근차근 다지고, 코드 버전 관리와 실제 서비스 배포 개념까지 실무 흐름 전체를 다뤘습니다.

실제로 주차별로 어떤 활동과 효과가 있었는지 이어지는 슬라이드에서 하나씩 보여드리겠습니다.

# 2월 4주차 · 코딩 기본 문법 · 변수·함수

커리큘럼의 첫 출발인 2월 4주차에는 개발 실무자인 운영진이 선별한 파이썬 강의로 프로그래밍 언어 기초를 닦았습니다.

멤버들은 기본 문법과 변수·함수를 익히며 프로그래밍 기초 체력을 길렀고,
이를 통해 이후에 이어질 PoC 개발과 실습에 망설임 없이 참여할 수 있는 단단한 출발점을 만들었습니다.

# 3월 1주차 · 웹·시스템 구조 · 바이브 코딩
그 다음 3월 1주차부터는
바이브 코딩과 웹 시스템 구조를 중심으로 본격적인 실전에 들어갔습니다.

프론트엔드와 백엔드의 역할, 그리고 클라이언트–서버–API로 이어지는 데이터 흐름을 머릿속에 그리고
동시에 CLI, 터미널 같은 개발 필수 용어들을 맞추면서,
이후 시스템을 개발할 때 낯선 개발 용어 때문에 흐름이 끊기지 않도록 팀의 공통 언어를 확실하게 정립했습니다.

-------------------
# 3월 2주차 · API · SQL · CRUD 실습 
네, 다음 주차에는
PoC 구현에 핵심이 되는 API와 데이터베이스에 대해서 학습했습니다.

API를 보고 요청과 응답 흐름을 확인하면서 클라이언트-서버 통신을 AI와 함께 구현해보았고, 
테이블 생성부터 데이터 조회·수정 같은 실습도 진행했습니다.

이 과정을 통해 통신 구조를 이해하고 데이터베이스 기초를 확보하면서,
자신의 PoC에 직접 DB를 연동할 수 있는 기술 기반을 마련했습니다.

-------------------
# 3월 3주차 · 생성형 AI · LLM · RAG

그 다음 주차에는 요즘 가장 뜨거운 생성형 AI, LLM, RAG를 집중적으로 다뤘습니다.

머신러닝·딥러닝 기초부터 NLP와 LLM의 차이, 프롬프트 파라미터 조율법까지 폭넓게 실습했고

사내 복지 가이드인 '슬기로운 DRB 생활' 데이터를 활용한 RAG 챗봇을 모든 멤버들이 직접 제작해봤습니다.

개념 이해를 넘어, 사내 데이터를 활용한 LLM 챗봇을 내 손으로 직접 구현해보는 주차였습니다.

-------------------
# 3월 4주차 · RAG 챗봇 · 개인 발표
그리고 이어지는 주차에서는 
전 주에 배운 내용을 바탕으로 각자의 현업 데이터로 만든 RAG 기반 챗봇을 공유하는 시간을 가졌습니다.

각자의 현업 문제를 풀기 위해 어떤 고민을 했는지 발표하고, 
답변 정확도 개선법이나 최적의 모델 선택에 대해 질의응답을 나눴습니다.

이를 통해서 현업 도메인 문제에 AI를 직접 적용하는 실전 감각을 익히고, 동료들의 노하우까지 함께 흡수할 수 있었습니다.

-------------------
# 3월 4주차 · RPA 자동화
같은 주에는 워크플로 자동화 툴인 n8n을 활용해 RPA 자동화도 마스터했습니다.

RSS 피드를 받아 ChatGPT로 요약한 뒤 Teams로 자동 전송하는 파이프라인과, 엑셀 기반 발표 순서 자동화 등을 실습했습니다.

복잡한 백엔드 코드를 짜지 않고도 강력한 자동화 흐름을 만들 수 있게 되면서, 실무에 즉시 쓸 수 있는 RPA 자동화 역량을 확보했습니다

# 4월 1주차 · PoC 기획 · 아이디어 워크숍
다음으로 4월 1주차에는
개인별 PoC의 완성도를 높이기 위한 아이디어 워크숍을 열었습니다.

각 팀의 병목 업무와 현업에서 벌어지는 반복 수작업에 대해 정의하고, 
이를 AI로 어떻게 해결할지 토론하며 실행 가능한 설계 초안을 잡았습니다.

이 시간을 통해서 현업에서 해결하고자 했던 문제들을 
단순한 아이디어로 남기는 것에 머무르지 않고, 
개발에 적용할 수 있는 명확한 솔루션 기획안을 도출해냈습니다.

# 4월 3주차 · API 개발 심화 · 사내 LLM 연동

다음으로 4월 3주차에는 API 심화 개발과 사내 LLM 연동을 다뤘습니다.

FastAPI라는 프레임워크를 도입해 요청과 응답을 정교하게 제어하고 
AI 도구에 API 설계를 지시하고 코드를 받아내는 고급 프롬프팅 방식도 익혔습니다.

이로써 사내 LLM 연동과 API 설계 역량이 한층 강화되어, 
각자의 PoC에 필요한 백엔드 기능을 스스로 설계하고 검증할 수 있게 되었습니다.

# 4월 3주차 · Git · GitHub
같은 주에 코드 관리와 협업의 필수 도구인 Git과 GitHub도 학습했씁니다.

내 PC에서만 작업하던 것을 넘어 원격 저장소로 코드를 올리고(Push) 내려받는(Pull) 실무 흐름과 기본 명령어들을 손에 익혀

현재는 모든 멤버가 PUG GitHub를 통해 코드를 관리하고있고
개발 실무자와 소통하는 데 문제가 없도록 코드 버전 관리 역량을 갖추게 되었습니다.

-------------------
# 4월 4주차 · BackEnd · FrontEnd · API 연동
이어서 Webhook과 전체 서비스 배포 흐름을 연결했습니다.

API로 웹훅 서버를 구축해 요청을 처리하고, 
프론트엔드 화면부터 서버, n8n, 그리고 Teams 알림까지 전체 파이프라인이 매끄럽게 이어지도록 실습했습니다.

프론트와 백엔드, DB가 실제로 어떻게 맞물려 돌아가는지 체득하면서, 
껍데기만 있는 화면이 아니라 실제 동작하는 엔드투엔드 서비스 구조를 완성했습니다.

-------------------
# 4월 4주차 · UI/UX 기초
같은 주에 화면의 완성도를 결정짓는 UI/UX 기초도 다졌습니다.

단순히 디자인만 하는 것과 달리
실제 사용자의 경험을 생각하며 디자인 하는 것의 차이에 대해 배우고, 
Google Stitch 같은 AI 툴을 통해 디자인 전문가의 도움 없이도 UI 시안을 만드는 실습을 진행했습니다.

기능 구현에만 급급했던 단계에서 벗어나 사용자 중심 설계를 고민하게 되면서, 
실제 사용자가 쓰기 편하고 직관적인 화면을 기획할 수 있게 된 주차였던 것 같습니다.

단순 질의응답을 넘어, 복잡한 업무를 스스로 쪼개서 수행하는 자율형 에이전트 구조를 설계하는 역량까지 확보하게 되었습니다.

# 멤버별 역량 성장

이러한 12주간의 집중적인 교육과 실습을 거치며 멤버들의 기술적 역량도 크게 성장했는데요.

AI 관련 기술 영역의 40개점검항목 기준으로 성장세를 측정한 결과,
전체 평균 달성률은 PUG 활동 초기 28% 대비 89%로, 약 +61%p 상승했습니다.

AI 에 대한 경험이 아예 없는 멤버들부터 시작해 출발선은 모두 달랐지만,
모든 멤버가 40개 중 30개 이상의 실무 역량 지표를 달성하면서 
이제는 PUG 멤버 전원이 스스로 AI 서비스를 기획하고 구현할 수 있는 실전 역량을 갖추게 되었습니다.

# AI PUG Showcase · 멤버 PoC 발표
이 모든 주차의 여정과 협업의 결과로 상반기를 마무리하는 **AI PUG Showcase**를 개최했었는데요.

이중 일부 사례를 요약해 말씀드리겠습니다.

첫 번째로, 김보근 님의 'AI 회의 비서'입니다.
참석자들이 10명 가량 되는 회의 하나 잡으려면 참석자들 일정 확인과 빈 회의실 찾기위해 번거로운 과정이 참 많았습니다.
AI 회의비서 MOMO를 사용한다면 이제 메신저에 "다음 주 화요일에 김동일님과 회의 잡아줘"처럼 자연어로 툭 던지기만 하면, 
아웃룩과 그룹웨어 API를 통해 비어있는 시간과 회의실을 알아서 찾아 예약하고 
아웃룩 캘린더 등록과 회의실 예약까지 원스톱으로 끝낼 수 있게 되었습니다.
덕분에 번거로운 조율 과정과 소통 비용을 크게 줄여주었습니다.
 
두 번째는 강주혁 님의 'Check-Mate'입니다.
재무팀 결산 업무는 기한과 정확성이 생명인데, 그동안은 진행 순서나 현황이 엑셀에만 흩어져 있어서 전체 흐름을 한눈에 파악하기가 어려웠습니다. 
이를 해결하기 위해 재무팀 업무 플로우를 한 눈에 확인하는 시스템을 개발해서 
결산 절차의 전후 관계를 플로우맵과 간트차트로 시각화했습니다. 
그의 결과 신규 담당자도 업무를 빠르게 파악할 수 있게 되었고, 
병목 구간을 미리 짚어내며 결산 노하우를 회사의 지식 자산으로 축적했습니다.

세 번째는 현재호 님의 'VEDA'입니다.
메일, Teams, 노션처럼 업무 기록이 제각각 흩어져 있다 보니 필요한 사내 자료를 찾는 데 시간이 꽤 많이 들었습니다. 그래서 외부 유출 걱정 없는 온프레미스 LLM 기반으로 다양한 소스를 통합 검색하고, 출처가 명확한 근거 기반 답변을 제공하는 시스템을 만들었습니다. 검증 결과도 문서 검색 정확도를 최대 90% 이상으로 끌어올리면서 실무 질문에 신뢰도 높은 답변을 바로 찾아주고 있습니다.
 
1부 마지막은 강응준 님의 'ATHENA'입니다.—:—
사내외 정보는 넘쳐나지만, 단순히 모아두는 것과 의사결정에 쓸 지식으로 가공하는 건 완전히 다른 문제였는데요. 자료를 수집해 분류해 두면 여러 AI 에이전트가 알아서 요약과 심층 분석, 팩트체크까지 나눠서 수행합니다. 흩어진 원천 데이터를 검색이나 보고서 작성에 즉시 활용할 수 있는 알짜 지식 자산으로 탈바꿈시켰습니다.

# AI PUG Showcase · 멤버 PoC 발표
이어서 2부 사례입니다.

먼저 윤성수 님의 '러버트랙 BOM'입니다.
신제품 견적을 낼 때마다 SAP 데이터와 BOM, 엑셀을 일일이 대조해가며 부품을 바꾸는 수작업이 반복되곤 했습니다. 
이를 해결하기 위해 단가표만 올리면 자동으로 분류해 재료비를 계산해주고, 
자연어로 부품을 조회·수정하는 에이전트를 개발했습니다. 부품 조회 시간을 대폭 줄인 것은 물론, 담당자 숙련도에 상관없이 계산을 표준화하고 휴먼 에러를 방지했습니다.

다음은 김진용 님의 '임가공비 분석'입니다.
외주 견적서가 들어왔을 때 금액이 적정한지 판단하기 어렵고, 
담당자의 경험에 따라 절감 기준도 제각각이었던 문제가 있었습니다. 
그래서 업체 견적서와 DRB 표준 시트를 비교해 과다 청구액과 협상 권장가를 3단계로 검증하는 시스템을 구축했습니다. 
한 시간 가까이 걸리던 검토 작업을 단 몇 초 만에 끝내고, 객관적인 협상 근거와 검토 기준을 확립하게 되었습니다.

세 번째는 박지훈 님의 '수율 대시보드'입니다.
스크랩이나 불량, 수율 데이터가 여러 엑셀로 쪼개져 있어 데이터를 모으고 원인을 분석하는 데 손이 많이 갔습니다. 이 데이터들을 DB로 모아 대시보드로 시각화하고, "지난달 특정 라인 불량 원인이 뭐야?"처럼 자연어로 물어보면 바로 분석해주는 기능을 붙였습니다. 데이터 접근성을 높이고 수작업 취합 시간을 획기적으로 줄였습니다.

마지막으로 박다솜 님의 '촉각 센서 분석 자동화'입니다.
하중 데이터와 정전용량 신호가 각각 따로 출력되다 보니 신호 동기화도 어렵고 분석자마다 해석 결과가 달라지는 한계가 있었습니다. 이를 신호 구간 감지부터 동기화, 보정, 리포트 생성, 해석 챗봇까지 전 과정을 자동화했습니다. 그 결과 분석 시간을 기존 대비 약 8분의 1 수준으로 대폭 줄였고, 결과 포맷을 표준화해 데이터 신뢰도를 확실히 높였습니다.

이처럼 쇼케이스를 통해 서로의 기술과 접근 방식을 공유하며, 
AI를 통한 업무 혁신 아이디어가 조직 전체로 자연스럽게 확산되는 계기를 만들 수 있었습니다.

# AI 활용 문화, 조직에 뿌리내리다
네. PUG가 처음부터 지향했던 **AI 문화 확산**은, AI를 잘 쓰는 사람이 늘어나는 것만을 뜻하지 않았습니다.

표와 가운데 그림처럼 

AI활용이 **도구 중심**에서 **문제 해결**로, 
학습이 **실행**으로, 
경험이 **함께 피드백**하는 방식으로 이어져갔고,

**AI 사용법**을 넘어 **현업을 AI로 풀어보는 문화가** 자리잡기 시작했습니다.

그래서 출범 때부터 내세웠던 **AI 문화 확산**이라는 슬로건을, 
조직 안에서 실제로 달성해 가고 있다고 볼 수 있습니다.
